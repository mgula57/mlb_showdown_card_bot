# Showdown Bot design language

A modern, flat app with a handful of touches lifted straight off the 2000–2005 MLB Showdown cards. The structure stays quiet so the numbers and the cards do the talking.

Every new screen and component follows this document. If something you need isn't covered, extend this file in the same change rather than inventing a one-off style.

Visual reference: the approved style guide artifact (Showdown Bot Design Language) shows each rule below rendered in light and dark.

## Three rules

1. **Modern base.** Plain surfaces, one small corner radius, hairline borders, no decorative gradients (the search frame's navy-to-red border is the one exception). Body copy, forms and controls look like a clean modern app.
2. **Period accents in five places only:** headings, labels, numbers, badges and frames. Never on body text. Texture stays at the top of a page (`PinstripeBackdrop`) and never runs behind the whole page.
3. **Numbers are the hero.** Points, On-Base, Control and chart ranges get the card's treatment: tabular figures, set in plates or the command badge.

## Color

All colors come from tokens in [`src/index.css`](src/index.css). Components never use raw Tailwind palette colors (`blue-500`, `green-600`) or hex values. Light mode is a pale 2001 card-back silver; dark mode is a navy-tinted near-black.

| Role | Token | Notes |
|---|---|---|
| Page background | `--background-primary` | Silver in light, near-black in dark |
| Panels, inputs, chart boxes | `--background-secondary` | White in light |
| Quiet fills, skeletons, table headers | `--background-tertiary`, `--background-quaternary` | Silver steps |
| Release and league tile field | `--release-tile-field` | A deeper silver in light mode, returning to the existing tertiary surface in dark mode |
| Hairline borders | `--divider` | Default border for everything |
| Strong rule | `--rule-strong` | Frames, hover borders, `shadow-raised` edge |
| Text | `--text-primary`, `--text-secondary`, `--text-tertiary` | Tertiary is captions and meta |
| Brand | `--showdown-blue`, `--showdown-red` | Navy for primary actions, selection and frames; red for the active tab and emphasis. As text, borders, rings and tints |
| Brand fills | `--showdown-blue-fill`, `--showdown-red-fill` | Solid fills that carry white text: primary and feature buttons, navy and red plates, count badges, mode bars. Equal to the brand colors in light; a shade darker in dark so white text keeps 4.5:1. Write `bg-(--showdown-blue-fill)`, never a solid `bg-(--showdown-blue)` |
| WOTC comparison bars | `--chart-compare` | Red in light mode and blue in dark mode to distinguish the reference series from the set's dark bars |
| Stat plates | `--plate`, `--plate-ink` | Silver plate in light, raised gray plate in dark. Team-color fields use the dark `onField` plate instead |
| Status | `--green`, `--red`, `--warning`, `--success`, `--error`, `--live` | Semantic only, never decorative |
| Team-color fields | `--card-edge`, `--field-ink`, `--field-live` | Same in both themes; see below |
| Set badge outline | `--set-outline` | Letter outline on `SetBadge`: white in both themes, like the printed set logos (a dark outline muddied the letters on light surfaces) |
| Highlight gold | `--gold` | Starred teams, Hall of Fame, All-Star marks. Never decorative |
| Bronze | `--bronze` | Third-place medals only (1st is `--gold`, 2nd `--text-secondary`) |
| Grade scale | `--grade-a` … `--grade-d` | Percentile and match-quality readouts, best to worst (points breakdown, percentile gauges, card comps). Use `gradeColor(score, cutoffs?)` from `functions/colors.ts` |
| Heat scale | `--heat-hot`, `--heat-warm`, `--heat-cool`, `--heat-cold` | Real-vs-league percentiles, Statcast style, with `--rule-strong` in the middle. Use `heatColor(percentile)` |
| Table fills | `--table-header`, `--table-banding` | Data table header row and alternate-row banding |
| Sim readouts | `--advantage`, `--die-body`, `--die-ink` | The pitch-roll winner highlight and the d20 in the game sim |
| Category and state accents | `--challenge-legendary`, `--challenge-budget`, `--challenge-superteam`, `--challenge-themed`, `--preview-accent` | Team Challenge categories and the Release Builder's unsaved preview state. Identity colors only |

Older tokens (`--primary`, `--secondary`, `--tertiary`, `--quaternary`) still work. Prefer the `--text-*` names in new code. If you need a color that doesn't exist, add a token for both themes in `index.css` and list it here.

**Use the token syntax.** The legacy utilities in `index.css` (`text-primary`, `text-secondary`, `bg-primary`, `border-form-element`, …) are plain CSS classes, so a variant or opacity on them (`hover:text-secondary`, `bg-primary/10`, `@2xl:border-form-element`) never renders, and names that were never defined (`bg-background-secondary`, `bg-accent`, `text-md`) render nothing at all. Write `hover:text-(--text-secondary)`, `bg-(--background-primary)/10`.

A club with no colors falls back to `NEUTRAL_TEAM_COLOR` / `NEUTRAL_TEAM_COLOR_SECONDARY` from `functions/colors.ts`. They're real colors rather than tokens because they feed the contrast helpers.

**Team colors** appear only where a team is the subject: the team preview tile, the year/team plate (primary) and points plate (secondary) on a card, the command number, the out results on a chart. Pass them inline (`style`) from the card or team data, and run them through `getContrastTextColor` / `darkenIfLowContrastOnWhite` from `functions/colors.ts` for text.

## Type

| Role | Class | Use |
|---|---|---|
| Display | `font-display uppercase` | Headlines that stand alone: page and section titles, release names, team abbreviations and names on team tiles, tab labels, `feature` button labels. The bundled Helvetica Neue Condensed Heavy Oblique (already slanted, so never add `italic`) |
| Command number | `font-display-black` | On-Base and Control numbers in `CardCommand`. Helvetica Neue 107 Extra Black Condensed |
| Card name | `font-display-upright` | Player names and the year/team plate next to them on cards (`CardItem`, `CardItemCompact`), stat-badge values, game scores, and form section titles (`FormSection`), which sit inline with summary chips. Helvetica Neue Bold Condensed |
| Slab | `font-slab` | Alfa Slab One, only for `EmptyState` headlines: the heavy slab caps of the 2000 print ads. Self-hosted from `@fontsource/alfa-slab-one` |
| Eyebrow | `<Eyebrow>` | Small, widely spaced caps above a title |
| Page subtitle | `<PageSubtitle>` | The line under a `Heading level="page"`: secondary ink, `leading-tight` so a description that wraps on a phone stays one block with the title. `size="md"` (13px, default) for a description, `sm` (12px) for a count or short note. Never a hand-styled `<p>` |
| Field label | `FIELD_LABEL_CLASS` (`fieldStyles.ts`) | The label above every input, dropdown, picker and toggle group: 11px semibold body-face caps, lightly spaced, tertiary ink, like ON-BASE / SPEED on the card front. Hint text inside a label goes back to `normal-case` |
| Caps label | `CAPS_LABEL_CLASS` (`fieldStyles.ts`) | The field label's type with no color or `block`: group labels in a list ("Rotation", "Overperformers" in green), table column headers, inline labels ("On Deck"). Add the ink yourself, `text-(--text-tertiary)` unless it carries a status color. Caps labels of 7–9px inside plates and chart visuals are card-stat micro labels and stay as they are |
| Body | `font-sans` (Inter) | Inter, self-hosted from `@fontsource-variable/inter` and set as `--font-sans` (with the `cv05`/`cv08` alternates so l and I don't read as 1), so every element without a display class uses it. Paragraphs, controls, helper text, plates and caps labels. Weights stop at `font-bold`: no `font-extrabold` or `font-black`, since titles use `Heading` and standalone numbers the display face |
| Data | `tabular-nums` | Every number that lines up in a column, ranges, points |

The italic display face is loud, so it's only for a headline that sits on its own. It never goes inline next to upright plates or stats, which is why card names use the upright condensed face. Everything else on a card or tile (plates, stat lines, chart labels and ranges, set numbers, counts) uses the body face. The one inline exception is `SetBadge`, which prints a set's name in the italic display face because that's how the sets brand themselves. Paragraphs and descriptions always use the body face.

Display-face text never `truncate`s. The faces are wide, and the italic leans past its own box, so an `overflow: hidden` edge cuts off both long names and the slant of the last letter. A one-line title that can run long (a team, release or round name) uses `<Heading fit>`, or `FitText` for display text that isn't a heading (the team tile abbreviation). It shrinks from the CSS size down to `minScale`, then ellipsizes. Multi-line clamps (`line-clamp-2` on a release name) add `SLANT_ROOM_CLASS` from `headingStyles.ts`. So does italic display text that changes color itself (a `hover:text-*` link or button with no padding of its own, like the player name in `CardDetail`'s header): browsers repaint only the element's box on the color change, so without the room the lean of the last letter is left cut off. Padded controls (tabs, `feature` buttons) already have the room.

The display fonts' vertical metrics are normalized so capitals sit centered in their line box. Uppercase text in any display face centers in plates, badges and flex rows with plain `items-center` and `leading-none`, so never nudge it with offsets or padding tweaks. When adding or replacing a display font, run `uv run --with fonttools python frontend/scripts/normalize_font_metrics.py` (and add the file to its list).

Charts keep their compact footprint: don't increase cell padding, minimum widths or font sizes in `CardChart`, because cards are laid out around its width.

## Shape and depth

- **Corners:** `rounded-card` (5px) for panels and tiles, `rounded-control` (4px) for buttons and inputs. `rounded-plate` (2px) for plates, badges and skeleton bars, just enough to soften them at small sizes. `rounded-trading-card` (10px) echoes the printed cards' rounded corners, and only on tiles that stand in for a physical card: `CardItem`, `CardItemCompact`, `TeamPreviewCard`, `ReleaseItem`, `LeagueItem` and their skeletons. Never on panels, modals or table wrappers, which keep the one small corner. Anything pinned flush in a trading-card corner follows the curve (`rounded-br-trading-card`) or sits far enough in to clear it. Circles only for avatars, the command art and small status dots. No `rounded-xl` or larger, and no pills for counts or status (use a `Plate`).
- **Depth has three steps:**
  - **Flat:** 1px `--divider` border. Most things.
  - **Raised:** `shadow-raised`, a hard 2px bottom edge, for primary buttons and pressable tiles. `shadow-feature` is the same hard edge in Showdown red, 3px, only on `feature` buttons. A floating feature button (the circular Build Card and Run Algorithm buttons on mobile) uses `shadow-feature-float`, the red edge plus the overlay shadow.
  - **Overlay:** `shadow-overlay`, the only soft shadow, for modals, menus, sheets and floating buttons. `shadow-sheet` is the same shadow cast upward, for sheets and strips anchored to the bottom edge (`BottomSheet`, `SlideOver`, the docked Guided Draft strip).
- **No glass.** Overlays, sticky bars and footers are opaque surfaces (or a flat translucent fill over field art), never `backdrop-blur`. The one exception is what's laid over the top of the game field, the scoreboard and the tabs that grow out of it: `BOARD_OVERLAY_CLASS` (`boardStyles.ts`), mostly filled with the field blurred behind it, so the score reads cleanly over the outfield art. Modal and sheet scrims are a flat `bg-black/50`.
- **Keyboard focus** is a 2px `--focus-ring` (navy) outline offset 2px, from one unlayered `:focus-visible` rule at the end of `index.css` that covers buttons, links, tabs and checkbox roles and wins over `outline-none`. Text fields show focus with their navy border instead. Don't add per-component focus styles, and never remove the outline without a visible replacement.
- **Selection** is a navy outline: `border-(--showdown-blue) ring-1 ring-(--showdown-blue)`. Never an inverted fill (`bg-(--secondary) text-(--background-primary)`), which reads as a primary button, and never a glow. Rows of options use `choiceClass`. An active slot on the field art (`FieldView`) uses the white `--card-edge` ring instead, since navy disappears on the grass.

### Team-color fields

The team preview tile gets the full card-front look, because the team is the subject: the team color as the background under the faded ballpark art (`/images/teams/Field.png`) with a team-color wash at the top and a dark scrim under the roster, a white card edge (`--card-edge`) instead of a gradient border, `onField` plates, and the abbreviation in `font-display` with `text-outline-double`. Don't use this look on panels that aren't about one team.

### Game board

The game screen (`GameBoard`, in `GameStage`) treats the field as the surface of the page, and everything about the situation sits on it in named zones: the scoreboard along the top edge (the score, the inning, the bases with the outs, and on a wide board the linescore), the pitcher's and batter's `CardItem`s in the bottom corners on a wide board, and the field's own controls in the field's bottom corners on every board: the defense totals etched into the left-field foul ground along the third-base line (`.field-etched`: dark, semi-clear ink with a faint lit lower edge, so they read as pressed into the turf rather than a panel on it; the whole etching is the expand toggle, ending in an etched expand / collapse mark in the same ink so it reads as pressable), the player's own controls (a live game's Manager button) bottom right. Nothing floats in panels beside the scoreboard. The last play and whose turn it is grow out of the scoreboard's bottom edge (`ScoreboardIsland`). New board pieces get a zone in `GameBoard`, not a change to `GameField`. Panels on the board use `BOARD_PANEL_CLASS` (`boardStyles.ts`), a faint flat tint that lets the field show through. It's too sheer to hold secondary or tertiary ink, so text on it is `--text-primary`. The wide board's center panel (`MatchupCenterPanel`) numbers the plate appearance's rolls in the order they come: the pitch with its meter, the swing with its outcome odds, and any throw on a runner (a steal before the pitch, a double-play turn or an extra base after the swing) in its place, each with what it came to. Through an extra-base throw the hitter who swung stays in the matchup until the next one steps in. Outs, balls and strikes are small status dots. The sim's dice stay on the field beside the pitcher and the batter who rolled them, never in a panel. The same goes for a player-driven roll: its control belongs on the field at the die (`HandDie`, a tappable blank d20 docked where the roll will land). Each die is thrown on its own, never with another: a tapped die (or one rolled from the next-move button) is thrown right away: one short jump that rattles as it goes (`.hand-die-throw`). The other player's die is thrown the same way when their roll arrives. The face keeps scrambling until the die has landed, held still a beat, and the roll is back; only then does the number show, and whatever it decides (the advantage) waits for it. A roll that came in while the field was still playing out the last play is thrown when it first shows, so its advantage still waits on it. Card images zoom to what's being rolled on from the tap, not once the roll is back. Each roll also has copies of its die wherever its result is read (`RollMirrors`), so the eye never has to leave that spot: the pitch laid over both cards as a face-off (`PitchCompare`: an opaque panel with the die plus Control on the left and On-Base on the right across a red VS; once the number is up the sum holds on its own for a beat, then the winner's side fills navy or red, the other dims, and the advantage hangs off the top in a plate, still on the commands for a beat before the swing's result shows), the swing on the winner's chart (at the chart's edge, then sliding to the cell it lands on; the field holds still for a beat after the cell lights, so the eye reads the chart and then comes back up to the field for the result and the runners), a marker running along the center panel's meters, a small die in the rolling step's header, and the two rolls opening the last play's tab before its text. They all run off the one throw `GameStage` keeps per die, so they land on the same frame as the field's die. Only the field's die makes the throw; a copy wobbles and scrambles in place, then pops as the number comes up. The die keeps that face while the next roll is waited on. When the swing resolves, only the swing die is thrown; the pitch die keeps the face it already showed. Nothing spins while a roll is on its way. Each area of the board has one job on every screen size, so players learn where to look: the top is the game state, the field's bottom-right corner is the player's own club (a live game's Manager button, which opens a `RightPanel` with autopilot and substitutions so the board stays in view), and the field is the roll. Because a docked die is a small target, every board adds a thumb-sized next-move button beside the Manager button (`LiveActionButton`, which reads Pitch, Swing or Wait as the turn changes, so the spot never jumps); it rolls the same die. The corner controls (Manager, next move, the strategy hand opposite) share one shape, `BoardCornerButton` (`games/`): a square with an icon over a short label, raised, `primary` only when it's the move to make now, with a live dot in its corner when something behind it needs a look. New corner controls use it. Messages grow out of the bottom edge of the scoreboard in a `ScoreboardIsland` and fold back into it when there's nothing to say. Each is a tab with `rounded-b-card` corners, not a pill, and it hangs over the field rather than taking a row, always on top of it. The center tab is the last play: it drops when the play lands, stays out for a few seconds and folds back. Whose roll it is (and a move that failed) hangs under the side of the club the game is waiting on (`TeamStatus`). When a club makes a move (plays a strategy card, a pitching change, a pinch hitter), its team tab says that instead for a few seconds (`TeamAnnouncement`, worded with `TeamMoveNote`: the kind of move in caps, then the move), then goes back to the status. On a narrow board the center tab steps aside while an announcement is out, and a status waits while the last play is out, so they never overlap. The board's zones stay in a bounded block, centered across and pinned to the top so the score is always at the top of the page, and the field has a maximum width, so a large monitor gets more empty surround rather than a bigger board. The board's surface is the page background (`--background-primary`), not grass. The field is one piece of art drawn in perspective (`FieldArt`, built by `scripts/build_field_art.py`), cut out of its backdrop so it sits on either theme, with its far corners faded out so any host can clip them. Its deep outfield rises above the field box, and that's where the outfielders stand. Expanded, the fielders other than the pitcher are small single-row tags (`FielderMarker`: last name, the Gold Glove / Rookie icons, the rating at the position they're playing), not compact cards, so the pitcher, the batter and the runners stay the cards that stand out. Players on the field stand on a spot of ground (`FieldMarker`'s `grounded`, the resting form of the ring they kick up when they plop in), so they read as standing on the field, not pasted over it. A readout in a panel, like the runner rolls, isn't grounded. The board picks its layout from its own measured width, not the viewport, since the sidebar takes a varying share of it. Below `WIDE_BOARD_MIN_WIDTH` it stacks, with the same full `CardItem`s under the field (side by side when two fit, one above the other when they don't), so the chart is always there to show where a swing landed. Under them, the rest of the batting club's order ("Up next") runs as compact cards, each one a step fainter the further off it is, back to full on hover or focus. In the box score, the batter at the plate gets a tinted row and a red AB plate, and the fielding club's next hitter a quieter row and an outline Next plate (`LineupMarkPlate`, read from `LineupUpContext`, which `GameStage` provides so any host's tables can mark rows). A stacked field is zoomed (`NARROW_FIELD_ZOOM`), so first and third sit near the screen's edges rather than a phone's width going to foul ground; expanding it to show every fielder zooms back out. The scoreboard is laid over the top of the field, so the field runs up underneath it rather than stopping at its edge; it and the `ScoreboardIsland` tabs use `BOARD_OVERLAY_CLASS`, a mostly filled surface with the field blurred behind it, rather than the sheer `BOARD_PANEL_CLASS`. When a feed doesn't send a defensive alignment (a sim, a live game), the board fills it in from the box score lineup (`withLineupDefense`), so the OF / IF / CA totals and the expand toggle are always there. The play-by-play, box score and game info sit in a tabbed rail beside the board, so the situation never leaves the screen. A phone has no room for that, so it gets one row of tabs right under the top bar (Field, Plays, Box Score, Info), and each tab takes the whole page rather than opening a sheet under the field.

Strategy cards (the expert game's second deck, `components/games/strategy/`, handed to `GameStage` as `StrategyBoardSlots`) take the zones the same way. The hand is the field's bottom-left corner, opposite the player's own controls and the same thumb size as the next-move button (`StrategyHandStack`: a fan of navy card backs with the count, dotted when a card can be played now). Opening it lays the hand out in a tray rising over the bottom of the field (`StrategyHandTray`, an overlay, so it may take `shadow-sheet`): cards that can be played now sit raised, the rest are dimmed with the reason they can't ("Defense only", "Plays after a result"). Each card's kind is its color, as on the printed cards: offense red, defense navy, utility silver (`StrategyCardFace`). The moment the at-bat is at and whose call it is (before the pitch, on a result, after a result) grows out of the scoreboard's island with a Pass button, and on a narrow board the next-move button reads Pass or Wait until the window closes. A window where this player has nothing playable passes for them, so play only stops when there's a choice. A played card drops from under its club's side of the scoreboard (a team tab, below), then lands on the hitter's card (batting club) or the pitcher's (fielding club) as a one-line mini card (`PlayedStrategyCards`), so the matchup shows everything bearing on the at-bat; one that stays in play past the at-bat carries an outline In play plate.

### Frames

The 2001 card-back double rule (outer `--rule-strong` border, a gap, inner `--divider` hairline) with a diamond "base" on each corner (`<FrameCorners />` inside the framed element) marks feature tiles like a release tile, a league tile or a finished card. `FramedTile` (`shared/`) is the whole frame for a tile, pressable with an `onClick`. A framed tile takes the `rounded-trading-card` corner with `rounded-card` on the inner hairline, and the bases sit on the curve of the outer rule. Use it for about one kind of thing per screen, never ordinary panels, and leave at least a 12px gap between framed tiles so neighboring bases don't touch.

### League tiles

A league's tile (`LeagueItem`) is the pennant race: one pennant per seat hanging from a rail on the silver field, in that team's colors with its abbreviation, longest for the best record. A league has several teams, so team colors stay on the pennants and the field stays neutral. The team on the clock hangs at full length and pulses, the viewer's team carries a white base, the champion a gold star, and open seats hang as faint empty pennants. The tile fills its grid cell rather than taking a card's portrait shape, because twelve pennants need the width.

### Carousels

A sideways-scrolling row of cards or tiles uses `<CarouselRow>` (`shared/`). It bleeds through its container's horizontal padding (negative margins, the same padding added back inside the scroller), so at rest the first item lines up with the content above it and, once scrolled, items run to the container's edges instead of being cut off at an invisible inner margin. Pick the `gutter` that matches the parent's padding (`panel` for `p-5` panels, `page` for Home's `px-6 md:px-8`, `ticker` for the Today's Games body, `seasonsTab` for Seasons tab content), add a gutter when a new padding needs one, and give a bordered parent `overflow-hidden` so the bleed stops at its border. Items set their own width with `shrink-0` (`w-72` for `CardItem`). Don't hand-roll `overflow-x-auto` rows with an inner margin, or with no padding at all.

### Height-locked layouts

A screen that pins its header and scrolls panes inside (`h-[calc(100dvh-2.5rem)] overflow-hidden`) gates the lock on height as well as width: `md:tall:` (or `split:tall:`), never a width breakpoint alone. Wide but short screens (a foldable's inner screen, a landscape tablet, a small laptop window) would otherwise spend most of their height on the pinned header. On `short`, the page scrolls instead: the header moves away and the pane area takes the full viewport with `md:short:flex-none md:short:h-[calc(100dvh-2.5rem)]`, so its panes keep their own scrolling. The `tall`/`short` variants (45rem, 720px) live at the top of `index.css`, mirrored for JS by `SHORT_SCREEN_QUERY`. On `short`, headers also compact: tighter padding, a smaller crest, `h-8` actions, and secondary meta lines hidden (see Team Detail). Team Detail, the Release Builder and the game screens (`GameStage`, `GameDetail`) follow this.

### Motion

Motion is short and functional: a press, a panel opening, a die landing. When the viewer asks for reduced motion, one global rule at the end of `index.css` collapses animations and transitions to an instant, except spinners (still turning, slower, because they mean work is in progress). Don't add per-component `motion-reduce:` variants for ordinary motion; the global rule covers it. Signature effects that need a different reduced state (the dice toss, the advantage glow, the home reel's autoplay via `usePrefersReducedMotion`) define their own.

### Loading

Skeletons use the silver surface (`--background-tertiary`) and match the dimensions of the content they stand in for, plates included.

### Empty states

Screens with nothing to show borrow the voice of the 2000 print ads: `<EmptyState>` (`shared/`) sets a short, confident slab-serif caps headline ending in a period ("NO TEAMS YET.", "BE THE FIRST."), one plain line under it, and the next step as a primary action when there is one.

- `page`: a screen or tab with nothing in it yet (your teams, your gallery).
- `panel`: an empty section inside a page (a challenge leaderboard, a release with no editions, an empty schedule day).
- `inline`: one quiet centered line, no headline, for a search or filter with no matches ("No teams match “xyz”.").

### Signed-out states

Anything gated behind an account uses `<SignInPrompt>` (`shared/`), never a bare grey line of text or a hand-wired `LoginModal`. `size="page"` (default) is for a screen or tab that needs an account throughout (your gallery, your account). `size="panel"` is for one gated part of an otherwise usable screen (the Releases page's create action); it is an `EmptyState` panel with a primary "Sign in / Sign up" button. The title says what signing in gets you ("Build your own release.") rather than naming the barrier, and the message is one plain line.

Short notes inside a dense panel row ("No awards won.") stay plain tertiary text. Never put the slab headline on a search miss.

## Copy

Write like the cards and the ads: short, confident, plain. Use baseball terms the way the cards print them (PT., ON-BASE, CONTROL, IP 7, SPEED B (15)). Buttons say exactly what happens ("Run algorithm", "Publish"). Labels are sentence case ("Send reset link", "Apply changes"); proper nouns and set names keep their capitals. Status messages are plain statements without exclamation marks ("Card built", "Filter saved", "Signed out"); errors say what failed and what to do ("Couldn't save your username. Try again."), without "please" or "successfully". In-progress labels end in a single ellipsis character ("Saving…").

## Set themes (future)

The app ships one theme. Components are built so a future theme for a specific set (2004, say) can restyle only these slots, keyed off the user's set preference or the set of what's on screen:

- Command badge
- Name and stat line
- Chart shape
- Background texture
- Set-number format

Layout, controls, body type, the palette and the display face never change between themes. Until a theme exists, keep set-specific styling out of components.

## Do and don't

**Do**
- Use tokens and the shared components above.
- Set aligned numbers in `tabular-nums`.
- Keep one headline number per screen in the command badge or a large plate.
- Give loading content a skeleton shaped like the result.
- Use `cursor-pointer` on everything clickable.

**Don't**
- Use raw Tailwind palette colors or hex values in components.
- Add decorative gradients, glows, glassmorphism or purple accents. The old drifting-gradient CTA classes (`animated-showdown-gradient`, `animated-team-gradient`) and the diagonal page gradient (`gradient-page`) are gone from `index.css`: primary actions use `buttonClass('primary')`, and pages sit on the flat `--background-primary`.
- Use `rounded-md`/`rounded-lg` (between the control and card corners), `rounded-xl` or larger, or pills for status and counts.
- Write a raw `<h1>`–`<h6>`, or style a title with large bold body text. Use `<Heading>`.
- Restyle a `CustomSelect` with `buttonClassName`. Use its `size`.
- Hand-style a field label or build a switch or checkbox. Use `FIELD_LABEL_CLASS` and `FormEnabler`.
- Use soft shadows on anything that isn't an overlay.
- Set body copy or long text in the display face.
- Branch on `isDark` for colors. Tokens already switch with the theme.
- Build class names from variables (`` `border-(${tone})/30` ``). Tailwind can't see them, so they never render. Map each state to a full class string instead (see `OUTCOME_TONE_CLASSES` in `SimResult`).

## Enforcement

`npm run lint:design` checks the mechanical rules on lines changed since `master`: raw palette colors, hex in classes, large and in-between corner radii, arbitrary or Tailwind-scale radii in place of `rounded-plate`/`rounded-control`, pills, raw heading tags, large bold body text used as a title, hand-styled field labels and caps labels, extrabold and black weights, hand-built tabs and filled buttons, hand-built toggles, restyled selects, soft shadows and decorative gradients. `-- --base HEAD` checks only uncommitted work, `-- --all` prints a full audit of `src/`, and `-- --all --list` adds every location. The lint can't judge everything (whether a title picked the right level, whether a new control matches its neighbors), and it reads one line at a time, so it misses multi-line class strings, colors passed as props or inline `style` (hex fallbacks, `rgb()` scales), `backdrop-blur` glass, `italic` body text, classes that never render (see "Use the token syntax"), spinners where a skeleton belongs, and buttons without `cursor-pointer`. Compare new UI against an already converted screen too. The Tailwind CSS IntelliSense extension separately suggests canonical forms for arbitrary values (`p-[3px]` → `p-0.75`); take those suggestions, except for corner radii, which use the `rounded-*` tokens above rather than Tailwind's `rounded-xs`/`rounded-sm` scale. If a line genuinely needs an exception, add a `design-ok: <reason>` comment on it or the line above. For a block (e.g. the edition and expansion identity colors in `customs/cardStyle.ts`, or the Google and Discord sign-in buttons in `LoginModal`, which follow those brands' own button colors), wrap it in `design-ok-start: <reason>` / `design-ok-end` comments. Reuse `cardStyle.ts`'s `expansionOptions` / `editionOptions` wherever expansions or editions are listed rather than copying their colors.

Run it alongside `npm run lint` and `npm run type-check` before finishing frontend work.
